# 使用教程

所有操作都用仓库根目录的 `run.sh`。`./run.sh help` 列出全部命令。

## 1. 第一次使用

```bash
git clone git@github.com:xhy-yyy/find_circle.git
cd find_circle
./run.sh setup
```

`setup` 会检查依赖、编译 ED_Lib、跑冒烟测试，最后打印"安装完成"。

缺依赖时它会列出缺什么。Ubuntu 上一条命令补齐：

```bash
sudo apt install cmake g++ libopencv-dev python3-opencv python3-numpy python3-yaml python3-pytest
```

Jetson 上 OpenCV 一般随 JetPack 装好，不要再装 Ubuntu 源的 OpenCV，其余照上面补。

## 2. 测图片

```bash
./run.sh image                         # 测 ~/桌面/无人机下视圆环图片 下所有图片
./run.sh image 图片.png 文件夹/          # 测指定的图片或文件夹
```

终端每张图打印一行，下面是找到的环：

```
01_黄沙空地_晴天_1080p.png  1920x1080  ...  通过 1  4275 ms
  #1 [EDCircles，白度通道] c=(761.2,627.9) r=8.8 扇区=16/16 ...
```

- `通过 0` 表示这张图上没有能首锁的环。
- 方括号是检测来源：`EDCircles`（全图检出）、`匹配滤波+局部EDCircles`（小环，放大后检出）；带"白度通道"的是在 min(B,G,R) 通道上通过的。
- 标注图在 `out/images_日期_时间/`：绿圈是结果，底部是放大图。

找不到环时排查：

```bash
./run.sh image 图.png --probe 761,628,9    # 在 (761,628)、半径 9 处直接复核，打印哪一项没过
./run.sh image 图.png --all                # 也列出只靠匹配滤波通过的，并画出未通过的候选和原因
./run.sh image 图.png --click 760,630      # 模拟点击，只在点击框里找
```

## 3. 测视频

**视频必须给点击位置**，否则程序不搜索，全程输出 LOST。

```bash
./run.sh video 降落.mp4 1160,600       # 第 0 帧在 (1160,600) 点一下（原图像素）
SHOW=1 ./run.sh video 降落.mp4         # 弹窗播放，用鼠标点
```

弹窗里：鼠标左键 = 点击，空格 = 暂停，r = 重置，q = 退出。不知道环在哪就用弹窗。

结束时打印各状态的帧数和耗时。标注视频和逐帧结果在 `out/video_名字_日期_时间.mp4 / .jsonl`。

相机测试录像可手动清理：`./run.sh clean --dry-run` 预览，`./run.sh clean` 删除。默认只匹配 `~/find_circle_rec/raw_日期_时间.avi`，跳过正在使用的录像，保留结果日志；设置过 `REC_DIR` 时，清理使用同一个目录。

## 4. 机载运行

配置写在 `run.sh` 开头，也可以在命令前用环境变量临时改：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DEV` | /dev/video0 | 相机设备，`ls /dev/video*` 查看 |
| `SIZE`、`FPS` | 1920x1080、30 | 分辨率和帧率 |
| `CALIB` | 空 | 相机标定 yaml（ROS camera_info 格式）。不标定时 bearing 误差可能超过 30% |
| `EXPOSURE` | keep | 默认保持相机原有曝光和对焦设置；`auto` 主动恢复自动曝光；数字为手动曝光，单位 100 µs |
| `UDP_OUT` | 空 | 结果发到哪里，例如 `192.168.1.10:9000`；空 = 打印到屏幕 |
| `LISTEN` | 9001 | 接收点击、高度、重置的端口 |
| `REC_DIR` | ~/find_circle_rec | 录像和结果日志的目录；设成空就不录 |

```bash
./run.sh camera                                              # 用默认配置
UDP_OUT=192.168.1.10:9000 CALIB=cam.yaml ./run.sh camera     # 发给飞控
SHOW=1 ./run.sh camera                                       # 带画面（机上有屏幕时）
```

启动后先打印录像路径、输出地址和输入端口，Ctrl+C 结束。

Orin Nano 更新代码后先运行 `./build.sh`。默认自动选择 CUDA 运动估计，不可用时回退 CPU，启动信息会打印实际后端；要检查 GPU 是否可用：`./run.sh camera --set motion.backend=cuda`。CUDA 模块须由当前 OpenCV 构建提供，不能仅凭系统安装了 CUDA 判断可用。

香橙派同样先在板端运行 `./build.sh`，再用 `SHOW=1 ./run.sh camera --set motion.backend=cpu --set track.template_backend=cpu --stats --quiet`。当前没有 RK3588 GPU 后端，使用 CPU 路径。

使用 `SHOW=1 ./run.sh camera --stats` 可同时看实际处理 FPS、漏处理帧数、算法 P95 和帧龄。重捕匹配也支持 CUDA，自动模式在模块不可用时回退 CPU；`--set track.template_backend=cpu` 可单独指定 CPU 匹配。

在线滤波默认开启，在圆环半径至少 8 px、几何和身份可靠时学习目标与周围背景；小圆仍走像素模板路径。滤波器使用 CPU，不需要预训练模型。丢失时只生成候选，圆心仍由几何复核输出。可加 `--set track.online_learning=false` 关闭滤波模块，在相同点击位置比较效果与耗时。

录像已移到有界后台队列，支持时直接保存相机 MJPEG 码流，结束时报告丢帧数。`REC_DIR="" ./run.sh camera` 可关闭录像和文件日志；`--record-mode encode` 强制后台软件编码。预览默认 15 FPS，识别不隔帧；需要时加 `--display-fps 30`。CPU 线程可用 `--threads 2` 或 `--threads 4` 对比选择。

- 1080p 录像每分钟约 200 MB，画面噪声大时更多，飞前确认空间够。录像和日志用来事后回放：`./run.sh video ~/find_circle_rec/raw_xxx.avi x,y`。
- 设置相机参数需要 `v4l2-ctl`（`sudo apt install v4l-utils`）。提示"没能设置曝光"时，用 `v4l2-ctl -d /dev/video0 -l` 看相机的控件名。
- 打印"实际分辨率与要求不同"时，相机不支持这个分辨率，用 `v4l2-ctl -d /dev/video0 --list-formats-ext` 查看，再改 `SIZE`。

## 5. 不起飞联调

开三个终端，在视觉机上演示整个接口：

```bash
# 终端 1：视觉，结果发到本机 9000
UDP_OUT=127.0.0.1:9000 ./run.sh camera

# 终端 2：模拟飞控，显示收到的结果
./run.sh listen 9000

# 终端 3：模拟地面站和飞控发输入
./run.sh click 0.60 0.56      # 点击，0~1 归一化坐标（相对原始图像宽高）
./run.sh height 85            # 离地高度，米；null = 不可靠
./run.sh reset                # 清除点击和目标
```

终端 2 每条显示一行，例如：

```
#68 DETECTED  TRACK  id=1 圆心=(1149.6,601.4) r=14.5 bearing=(0.198,0.064) 点击=- 扇区=16 延迟=102ms
```

- 点击后、首锁前是 `LOST SEARCH`，"点击="有值。
- 锁上后是 `DETECTED TRACK`，"圆心="有值。
- `RAW=1 ./run.sh listen` 显示原始 JSON。
- 输入要从别的机器发时，加上视觉机地址：`TARGET=192.168.1.20 ./run.sh click 0.5 0.5`。

全部字段和飞控的用法见《白色石灰圆环识别_技术方案》（`docs/` 下）的接口一节。

## 6. 调参

参数和说明在 `ringdet/params.py`。不改代码，两种方式：

```bash
./run.sh image 图.png --set verify.lock_sectors=13           # 临时改一项，image/video/camera 都能用
PARAMS=my.yaml ./run.sh camera                               # 用 yaml 文件，只写要改的项
```

```yaml
search:
  click_box: 800          # 点击框边长（px），点击误差大就加大
verify:
  lock_sectors: 14        # 首锁扇区下限（满 16），降低会增加误检
track:
  lock_need_edcircles: true   # 虚线环、断续环要设 false，误检风险变大
```

改完跑一遍回归测试，确认没有变差：

```bash
./run.sh eval
```

它跑冒烟测试、点击评估（桌面测试图和合成图，含 JPEG 压缩后的结果）和合成下降，笔记本上约 1.5 分钟。主要看两项：

- **"误锁"必须一直是 0。**
- **"命中"不能下降。** 现在的基线：桌面图 16/17（JPEG 压缩后 15/17），合成图 28/30。

## 7. 常见问题

| 现象 | 原因和办法 |
| --- | --- |
| 视频、相机全程 LOST | 没点击。视频加 `x,y` 或 `SHOW=1`；相机用 `./run.sh click` 或地面站发点击 |
| 点击了还是 LOST | 默认已优先搜索半径 ≥ 4 px 的小环；确认点击映射、分辨率和高度输入是否正确。环没有足够可辨亮线、严重模糊或超出点击框时仍会拒绝锁定 |
| 找不到 libedcircles.so | `./build.sh`（`run.sh` 发现没编译会自动编译） |
| 找不到相机 | `ls /dev/video*`，改 `DEV` |
| 帧率很低 | 相机没走 MJPEG，或分辨率不支持；用 `--list-formats-ext` 查 |
| 只想看 EDCircles 本身的效果 | `python3 tools/run_edcircles.py 图片或文件夹 --grad 8` |
